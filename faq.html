Frequently asked questions

Find quick answers about access, Coder cloud workspaces, the AI Gateway, and common technical questions.

Topic

Accounts

Anyone with an active UCSB NetID (students, faculty, and staff) can sign in at coder.dreamlab.ucsb.edu and create a Coder workspace for the duration of the academic quarter.

Visit coder.dreamlab.ucsb.edu, click UCSB Login, and authenticate using UCSB Single Sign-On (via Google) with your UCSB NetID.

Users may create and use only one workspace at a time. Multiple active workspaces may be deleted without notice to conserve shared computing resources.

Topic

Workspaces

Each workspace is an Ubuntu Linux virtual machine with 4 vCPUs, 16 GiB RAM, and a 64 GB user data disk. It includes Docker, Pixi, R, Python (uv/uvx), Git, and GitHub CLI, plus optional RStudio Server, JupyterLab, and VS Code Web/Desktop. See the Coder Overview for full specifications.

Yes. Stopping a workspace releases active compute resources while preserving files in your persistent home directory during the quarter. However, deleting a workspace permanently removes all files, and all workspaces are automatically deleted at the end of each academic quarter. Always back up your data.

Workspaces automatically shut down (stop) after four hours of inactivity to conserve shared resources. You can restart a stopped workspace at any time by clicking the Start button.

Topic

AI Gateway

The DREAM Lab AI Gateway is an experimental service providing OpenAI-compatible API access (https://litellm.dreamlab.ucsb.edu/v1) to LLMs hosted by campus cloud providers. Anyone with a UCSB NetID can generate a personal API key via the API key manager.

No. Neither Coder Workspaces nor the DREAM Lab AI Gateway are approved for confidential, sensitive, or restricted data classified as P3 or P4 under UC data protection levels.

OpenCode is pre-installed and pre-configured on Coder Workspaces to work with both the DREAM Lab AI Gateway and College IT's AI Gateway. See Using AI Coding Agents and UCSB AI Commons API for setup instructions.

Topic

Troubleshooting

RStudio Server must be enabled when the workspace is first created; it cannot be added to an existing workspace. Back up any files you need, delete the workspace, and create a new workspace with Include RStudio set to Yes.

You can use the built-in File Browser from the workspace dashboard, send files between machines with uvx magic-wormhole, or connect to Google Drive with rclone. See our Transferring Files guide.

Email the DREAM Lab team at dreamlab@library.ucsb.edu or join the UCSB Carpentry Slack.
